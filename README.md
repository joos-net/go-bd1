### Задание 1

Опишите не менее семи таблиц, из которых состоит база данных. Определите:

- какие данные хранятся в этих таблицах,
- какой тип данных у столбцов в этих таблицах, если данные хранятся в PostgreSQL.

Начертите схему полученной модели данных. Можете использовать онлайн-редактор: https://app.diagrams.net/

Этапы реализации:
1.	Внимательно изучите предоставленный вам файл с данными и подумайте, как можно сгруппировать данные по смыслу.
2.	Разбейте исходный файл на несколько таблиц и определите список столбцов в каждой из них. 
3.	Для каждого столбца подберите подходящий тип данных из PostgreSQL. 
4.	Для каждой таблицы определите первичный ключ (PRIMARY KEY).
5.	Определите типы связей между таблицами. 
6.	Начертите схему модели данных.
На схеме должны быть чётко отображены:
   - все таблицы с их названиями,
   - все столбцы  с указанием типов данных,
   - первичные ключи (они должны быть явно выделены),
   - линии, показывающие связи между таблицами.

**Результатом выполнения задания** должен стать скриншот получившейся схемы базы данных.

### Решение
#### Таблицы
1. Таблица employee (Сотрудники) - Хранит персональные данные сотрудников и их текущие назначения (оклад, дата найма, ссылки на справочники).

|Столбец|Тип PostgreSQL|Описание|Ключ|
|-------|--------------|--------|----|
|employee_id|SERIAL|Идентификатор сотрудника|PRIMARY KEY|
|full_name|VARCHAR(255)|ФИО сотрудника| |
|salary|NUMERIC(10,2)|Оклад (рубли, копейки)| |
|position_id|INTEGER|Ссылка на должность|FOREIGN KEY|
|department_id|INTEGER|Ссылка на структурное подразделение|FOREIGN KEY|
|branch_id|INTEGER|Ссылка на филиал (адрес)|FOREIGN KEY|
|hire_date|DATE|Дата найма (в формате ДДММГГ)| 

2. Таблица position (Должности) - Справочник должностей.

|Столбец|Тип PostgreSQL|Описание|Ключ|
|-------|--------------|--------|----|
|position_id|SERIAL|Идентификатор должности|PRIMARY KEY|
|position_name|VARCHAR(100)|Название должности| |

Примеры: ведущий QA инженер, специалист, руководель проектов по интеграции и т.д.

3. Таблица department (Структурные подразделения) - Содержит названия подразделений и ссылку на тип.

|Столбец|Тип PostgreSQL|Описание|Ключ|
|-------|--------------|--------|----|
|department_id|SERIAL|Идентификатор подразделения|PRIMARY KEY|
|department_name|VARCHAR(200)|Название структурного подразделения| |
|department_type_id|INTEGER|Ссылка на тип подразделения|FOREIGN KEY|

Примеры названий: Центр компетенций QA Москва, Группа сервисной поддержки, Департамент Техническая поддержка.

4. Таблица department_type (Типы подразделений) - Справочник типов: Отдел, Группа, Департамент.

|Столбец|Тип PostgreSQL|Описание|Ключ|
|-------|--------------|--------|----|
|department_type_id|SERIAL|Идентификатор типа|PRIMARY KEY|
|type_name|VARCHAR(50)|Название типа (например, "Отдел")| |

5. Таблица branch (Филиалы) - Хранит уникальные адреса филиалов.

|Столбец|Тип PostgreSQL|Описание|Ключ|
|-------|--------------|--------|----|
|branch_id|SERIAL|Идентификатор филиала|PRIMARY KEY|
|address|TEXT|Полный адрес филиала| |

Пример: Краснодарский край, г. Краснодар, ул Путевая, д. 1.

6. Таблица project (Проекты) - Справочник проектов, на которые назначаются сотрудники.

|Столбец|Тип PostgreSQL|Описание|Ключ|
|-------|--------------|--------|----|
|project_id|SERIAL|Идентификатор проекта|PRIMARY KEY|
|project_name|VARCHAR(200)|Название проекта| |

Примеры: Итэлма Инженерный корпус, Севастополь ТВ, Газпромбанк Аквамарин АН,Гурзуф – но мы разбиваем на отдельные проекты, поэтому каждый уникальный проект получит свою запись.

7. Таблица employee_project (Назначения сотрудников на проекты) - Связь многие-ко-многим между сотрудниками и проектами. Позволяет хранить все проекты, указанные в поле «Проект на который назначен» (в исходных данных их может быть несколько через запятую).

|Столбец|Тип PostgreSQL|Описание|Ключ|
|-------|--------------|--------|----|
|employee_id|INTEGER|Ссылка на сотрудника|FOREIGN KEY|
|project_id|INTEGER|Ссылка на проект|FOREIGN KEY|
|(составной)|PRIMARY KEY|(employee_id, project_id)|PRIMARY KEY|

#### Связи между таблицами
|Связь|Тип|Пояснение|
|-----|---|---------|
|employee → position|Многие к одному|У одного сотрудника одна должность, но должность может быть у многих сотрудников.|
|employee → department|Многие к одному|Сотрудник работает в одном подразделении, в подразделении – много сотрудников.|
|employee → branch|Многие к одному|Сотрудник привязан к одному филиалу, в филиале – много сотрудников.|
|department → department_type|Многие к одному|У каждого подразделения один тип, тип может быть у многих подразделений.|
|employee ↔ project (через employee_project)|Многие ко многим|Один сотрудник может быть назначен на несколько проектов, один проект может включать несколько сотрудников.|
